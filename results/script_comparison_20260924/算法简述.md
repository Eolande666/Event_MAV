# script 算法简述

这套代码先找“同一像素在短时间里反复出现正、负事件”的区域，再检查该区域的事件运动是否像旋转，最后打分决定是否输出检测框。

1. **找候选**：按像素和时间排列事件，统计极性切换次数与时间覆盖。切换多、覆盖时间格多的位置更突出，经连通区域提取形成候选框。
2. **看重复活动 P**：判断是不是只切换了一次，是否在多个时间格继续切换，同时略微降低背景也很活跃的候选分数。这里的“持续”发生在一个窗口内部，不是原 persistence 模块的跨窗持续性。
3. **看空间结构 C**：检查这些有效像素是否比较紧凑、连成区域，而不是散落的点。
4. **看旋转 Rot**：取窗口最后9 ms的事件，分别由正、负事件的时间表面估计局部速度；用5×5块汇总速度，再检查两种极性是否能共享一个旋转角速度。用整体平移解释不了、又更像旋转而非拉伸或剪切时，分数更高。
5. **联合决定**：Q = 0.55 Rot + 0.30 P + 0.15 C，达到0.34就输出；最近中心关联用于保持ID。框的位置由候选内真实事件坐标分位数确定。

它与原算法最大的区别：原算法通过三条特征曲线的峰谷判断局部周期变化；script通过局部速度场拟合旋转，没有那套六项峰谷评分，也没有邻域分数与轨迹分数融合的第三级。

**必须注意**：旋转不可观测时 Rot=0，P和C的最大贡献仍达0.45，所以也可能通过0.34阈值。输出框不等于已经确认旋翼旋转。IOC预算耗尽的候选则不会输出。拟合角速度是事件速度场的模型参数，不能直接当成已验证的物理旋翼转速。

本轮用同一批FRED原始H5与同一30 ms时间窗比较三种方法；script其他参数使用其config.default.json，不按评测标签调参。
