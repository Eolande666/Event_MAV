# 当前保留的六段 FRED 素材

处理顺序：8 → 20 → 51 → 65 → 93 → 114。只处理 FRED 目录当前保留的这六个 ZIP。

每个序列文件夹包含：

- RGB_original.mp4：FRED 原始 RGB 图片按文件中的拍摄时间排序，30 fps，无检测框。
- Events_original.mp4：原始事件按 30 ms 时间窗口生成的红蓝视频，无检测框，1280×720、100/3 fps。
- Detection.mp4：与事件原视频逐帧对应，叠加当前仓库算法检测结果；原始分辨率，3 像素框线，Times New Roman 22 像素标签。
- detections.jsonl、windows.csv、parameters.json：检测结果、窗口统计和参数。
- RGB_timestamps.csv：原始 RGB 图片时间及文件名。
- annotations.txt：原始数据集的无人机真值；不输入检测器。
- status.json：本段处理状态；complete 才表示三份视频均已生成并通过全片解码核验。

全部完成后，combined 文件夹包含上述三种视频各自的六段合集，按序列号顺序首尾衔接，无四宫格、无白边。不同序列不具有统一已验证的拍摄日期，序列号顺序不宣称是真实跨场景拍摄时间顺序。

事件原视频与检测视频严格共享事件窗口和帧数。RGB 为相机图片序列，30 fps；与 100/3 fps 的事件视频不是同一帧率，不应按相同帧号逐一对齐，需参考原始时间戳。RGB 图片尺寸以源文件为准，不做缩放。

P1 等是当前窗口检测编号，非跨帧跟踪身份；3/6 等是峰谷评分，非置信概率。部分检测框仅数个像素，保持原始检测坐标，不人为放大。

第 114 段可复用之前完成的同一代码检测结果，但会重新解码目前 ZIP 中的事件并逐帧核对事件数量和窗口边界；全部一致才允许复用。其他五段重新运行仓库 process_window；采用 30 ms 窗口、其他默认检测参数。无训练，无全数据集精度评测。

进度：progress.md / progress.json；日志：run.log。
