# 扩张前真实像素覆盖过滤

本次针对 T174 单像素误报修正显著性阶段。新增 `--min-raw-component-pixels`，实验门限为 **3 个不同的原始像素坐标**；默认 0 可保持原版行为。

## 判定发生在哪里

在一个 30 ms 事件窗口内：

1. 从原事件坐标构建布尔占据图，尚未膨胀或平滑。
2. 按 8 邻域找连通区域，统计每个区域内不同 `(x, y)` 的数量。
3. 剔除只覆盖 1～2 个像素的区域。正负极性、不同时间、重复触发都不增加像素数。
4. 只把保留区域的事件送入正负事件显著图构建，然后执行原有空间容差扩张、正负交集和时间片累计。

门限为 3 时，面积恰好为 3 的原始区域保留；隔着空白像素的几个孤立点不能先靠膨胀连起来再冒充有效覆盖。
这是整个时间窗的原始空间覆盖，并非每一个极性/时间片各自满足 3 个像素。

需要关闭新过滤时设置 `--min-raw-component-pixels 0 --saliency-min-area 0`。

## 代码和变量

`evdetmav/saliency.py::raw_pixel_support_mask`：

- `x, y`：当前时间窗每条原始事件的像素坐标。
- `height, width`：传感器尺寸。
- `min_pixels`：每个原始连通区域所需的不同坐标数，0 关闭。
- `occupied`：原始坐标去重后的布尔占据图。
- `labels`：8 邻域连通区域编号；0 是背景。
- `count`：原始连通区域数。
- `sizes`：各连通区域的不同像素数，重复事件不重复计数。
- `keep`：达到门限的区域编号掩码。
- `event_keep`：映射回每条事件的保留掩码，只供显著图构建使用。
- `small_sizes`：被剔除区域各自的像素数。

`build_density_saliency` 在最前面调用该函数，然后才生成时间片正负图和执行扩张；调用方的原事件数组不会被改写。
`pipeline.py` 和显式关闭周期性的适配路径都使用同一前置过滤。CLI 与持续性运行器保存逐窗 `raw_*` 统计。
